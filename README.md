# WetlandShield

> 面向湿地生态监测、风险识别与辅助研判的智能化看板系统

![Vue 3](https://img.shields.io/badge/Vue-3-42b883) ![Vite](https://img.shields.io/badge/Vite-8-646cff) ![NestJS](https://img.shields.io/badge/NestJS-11-e0234e) ![pnpm](https://img.shields.io/badge/pnpm-10-ff6c37)

WetlandShield 聚焦湿地保护与生态环境治理场景，围绕“监测感知、态势展示、异常确认、处置记录、智能建议”形成统一的业务闭环。系统通过可视化大屏整合多源监测信息，帮助管理人员快速识别重点区域风险、理解变化趋势，并获得可执行的研判支持。

## 🌿 项目定位

湿地是维护区域生态安全、生物多样性和水文平衡的重要基础空间。面对湿地面积变化、水质波动、植被退化和外源扰动等问题，管理工作需要同时具备持续监测、异常识别、趋势判断和快速响应能力。

WetlandShield 面向这一需求，提供一套以任务为中心的湿地生态监测展示系统：

- 以统一大屏呈现关键指标、趋势图表与重点区域画像
- 以事件化方式展示风险处置动态和当前异常状态
- 以人工确认与处置记录承接现场管理动作
- 以智能建议提升预警研判与行动协同效率

## ✨ 核心能力

- 多维态势展示
  面向湿地监测场景展示降水、水位、植被覆盖、关键环境指标和重点断面画像等信息，支持在单屏内完成多维观察。
- 风险动态跟踪
  通过动态事件区持续呈现待核查、已闭环等处置状态，增强对当前风险进程的感知。
- 智能研判建议
  结合当前卡片内容与上下文信息生成专业化建议，并以流式方式返回结果，使建议形成过程可见、可感知。
- 人工确认与处置留痕
  支持对异常进行确认、对处理动作进行记录，并返回当前状态快照，形成基础业务闭环。
- 演示与扩展兼容
  当前可使用 mock 数据与临时存储方式完成展示和联调，也兼容后续接入正式数据服务与持久化存储。

## 🧭 典型使用场景

- 湿地生态监测中心的大屏展示
- 重点断面、水域边界与生态缓冲带的日常巡查辅助
- 水质异常、短时污染输入或环境扰动事件的快速识别
- 管理部门对监测结果、趋势变化和处置进度的集中查看
- 面向汇报、演示和场景验证的生态治理可视化展示

## 🔄 业务闭环

系统当前围绕以下流程组织能力：

1. 汇聚湿地监测相关指标与图表信息，形成统一展示界面。
2. 对重点区域与关键指标进行实时或准实时呈现，帮助识别异常征兆。
3. 由人工对异常进行确认，并记录处置动作。
4. 基于当前界面上下文生成辅助研判建议，支撑后续行动判断。
5. 返回当前记录与状态，用于持续跟踪异常是否进入处置或闭环阶段。

## 🏗️ 系统架构

### 展示层

- 前端采用大屏化可视界面，承担指标展示、地图底图、动态信息、建议输出和人工交互等功能。
- 页面面向 16:9 场景设计，同时保留基础响应式能力，便于在不同展示环境下使用。

### 服务层

- 后端统一提供业务接口，对前端屏蔽外部模型服务细节。
- 当前已支持智能建议接口代理，以及异常确认、处置记录和状态汇总能力。

### 数据层

项目目标数据架构采用：

- `Postgres`
  用于承载结构化业务数据，例如异常确认、处置记录、设备信息、用户与配置。
- `ClickHouse`
  用于承载高频时序监测数据、指标聚合结果、趋势分析与历史回放查询。

在当前阶段，系统也支持不依赖正式数据库的演示模式，用于快速完成业务流程验证与视觉展示。

## 🧪 重点监测指标与业务意义

WetlandShield 关注的并不是单一监测点或单一传感器数据，而是围绕湿地生态健康、环境扰动风险和管理响应效率构建的一组综合指标体系。当前看板重点承载以下几类指标表达：

- 水文与补给相关指标
  包括地下水埋深、水位变化、生态补水过程和阶段性降水情况。这类指标用于反映湿地水文条件是否稳定，帮助判断区域是否存在补给不足、水位异常波动或短时来水扰动等问题。
- 水环境相关指标
  包括浊度、导电率、溶解氧、氨氮等关键环境指标。这类指标直接关联水体质量变化，可用于识别外源输入、污染扩散、底泥扰动和局部生态压力升高等风险。
- 植被与生态状态指标
  包括植被覆盖率及其年度变化趋势，用于反映湿地生态系统恢复情况、植被稳定性和区域生态功能变化。该类指标对识别退化区域、评估修复成效具有重要意义。
- 降水与过程性环境变化指标
  包括近 30 日降水过程及其阶段变化，用于理解短期天气扰动对水位、水质和风险事件的影响，为异常波动提供背景解释。
- 风险画像与事件状态指标
  包括重点断面风险画像、风险处置动态、待核查状态和已闭环状态。这类指标帮助管理者从“发现问题”过渡到“跟踪问题”，形成事件化管理视角。
- 研判与处置辅助信息
  包括 AI 生成的预警研判建议、人工异常确认记录和处理记录。该部分并非单纯展示数据，而是将监测信息进一步转化为可执行的行动支持。

这些指标共同服务于三个核心目标：

- 识别湿地生态系统是否出现结构性变化或短时异常
- 判断异常更可能来自水文变化、污染输入还是生态退化
- 支撑管理人员快速完成确认、记录、研判与后续处置

从业务价值上看，这种指标组织方式能够避免仅展示“孤立数值”所带来的理解断裂。系统更强调将趋势、状态、风险和行动建议放在同一语境下呈现，使监测结果不仅可见，而且可解释、可跟踪、可响应。

## 🔌 对外接口概览

系统当前提供的主要接口包括：

- `POST /api/chat/completions`
  用于生成或流式返回智能研判建议。
- `GET /api/records/current`
  用于获取当前异常确认与处理记录快照。
- `POST /api/records/confirm-abnormal`
  用于提交异常确认信息。
- `POST /api/records/record-action`
  用于提交处置记录信息。

## 🐳 Docker 部署

项目提供了面向生产部署的单镜像方案：

- 前端在构建阶段生成静态文件
- 后端在构建阶段编译为运行产物
- Caddy 作为统一网关，对外提供静态资源服务与 API 转发
- 可按需启用自动 HTTPS，也可仅使用 HTTP

### 构建镜像

```bash
docker build \
  --build-arg API_PREFIX=/api \
  --build-arg CADDY_SITE_ADDRESS=:80 \
  --build-arg CADDY_ENABLE_HTTPS=false \
  -t wetland-shield:latest .
```

### 启动容器

```bash
docker run -d \
  --name wetland-shield \
  -p 80:80 \
  -p 443:443 \
  -e AI_BASE_URL=https://api.deepseek.com/v1 \
  -e AI_API_KEY=your_api_key \
  -e AI_MODEL=deepseek-chat \
  wetland-shield:latest
```

### 构建参数说明

- `API_PREFIX`
  同时作用于前端和后端，默认值为 `/api`。前端静态资源会将它烧录为请求前缀，Caddy 和后端也会使用同一路径。
- `CADDY_SITE_ADDRESS`
  Caddy 对外监听的站点地址。可使用 `:80`、`example.com`、`example.com:443` 等形式。
- `CADDY_ENABLE_HTTPS`
  是否启用 Caddy 自动 HTTPS。设为 `true` 时，且 `CADDY_SITE_ADDRESS` 为可公网访问的域名，Caddy 会自动申请证书；设为 `false` 时，将关闭自动 HTTPS。

### 运行时环境变量

- `AI_BASE_URL`
  上游 OpenAI 兼容模型服务地址。
- `AI_API_KEY`
  上游模型服务的访问密钥。
- `AI_MODEL`
  默认使用的模型名称。
- `AI_TIMEOUT_MS`
  上游请求超时时间，单位毫秒，可选。
